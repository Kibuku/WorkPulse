# WorkPulse Classroom demonstration

Demo URL: <http://127.0.0.1:5721>
Audience: Strathmore University
Recommended duration: 8–10 minutes

## Opening

> WorkPulse is the Brain and sensing foundation. Personal, Organisation and
> Classroom are different guardrail profiles around that foundation. Classroom
> adds three operating modes for managed learning devices.

Open **Classroom** from **WorkPulse spaces**.

## 1. Explain the three modes

### Normal learning

The institution's everyday baseline:

- harmful categories restricted;
- suspicious downloads and phishing flagged;
- general institutional AI policy;
- policy events rather than complete browsing history.

Open **View active baseline** to show device health, safeguards and the minimal
event model.

### Class session

A timed teaching environment that temporarily replaces the baseline.

Open **Open class demonstration**.

### Exam session

A formally approved deterministic environment. AI may explain the resulting
technical report but never decides whether a student cheated.

## 2. Demonstrate Class mode

### Before class

Explain that WorkPulse prepared the session using the permitted timetable,
course files, previously approved browser domains and lecturer corrections.

The existing WorkPulse tracker provides app, window, file, browser and calendar
signals. Semantic capture is the next shared Brain capability and will improve
understanding inside documents and AI conversations.

Show the AI-aware rules:

- exploration and comparison allowed;
- verification and attribution required;
- sensitive-data uploads blocked.

Approve **Our World in Data** for this class if useful.

Select **Confirm and start demo**.

### During class

Explain that the lecturer does not watch a feed of every website. Familiar
permitted activity stays quiet.

Show:

- device protection health;
- one reconnecting device;
- no policy failures;
- a student request for a legitimate research dataset.

Select **Allow for class**.

Emphasise:

> WorkPulse records a scoped policy decision. It does not label the student or
> infer misconduct.

### After class

Select **After class**.

Show:

- baseline automatically restored;
- minimal factual report;
- proposed course memory;
- lecturer or course-owner approval;
- 24-hour raw-event expiry.

## 3. Demonstrate Exam readiness

Return to **All operating modes** and open **View exam readiness**.

Show:

- approved policy version;
- examination platform check;
- browser and application policy;
- clipboard and external-storage controls where technically supported;
- one device requiring technical review;
- technical-event language.

Select **Run readiness demonstration**.

State clearly:

> This is the intended readiness and audit flow. WorkPulse is not yet being
> presented as a certified secure-examination environment.

## What works in this demonstration

- WorkPulse-integrated Classroom workspace;
- Normal, Class and Exam operating-mode workflows;
- class preparation and AI-policy review;
- access-request decision;
- deterministic exam-readiness logic;
- student-safe event language;
- retention and course-memory workflow.

## What is being built next

- semantic capture shared across WorkPulse profiles;
- event-triggered screenshots as temporary working evidence;
- OCR, redaction and semantic observations;
- isolated Personal, Organisation and Classroom vaults;
- managed browser extension;
- remote policy delivery and device enrolment;
- real institutional identity and audit.

## Questions for Strathmore

1. Which real course should become the design-partner workflow?
2. Which AI uses should be allowed, attributed, restricted or prohibited?
3. Which LMS, timetable and identity systems are currently used?
4. Are the target laboratories managed Windows devices using Chrome or Edge?
5. What should a lecturer see when a learner may need help?
6. What information must never be collected?
7. Who approves policies, retention and a supervised pilot?
